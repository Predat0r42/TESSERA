## Статус

Рабочий прототип на Flutter с реальным Lua-бриджем. `lua_state.dart`
уже реализован на `lua_dardo`, первые модули `clock`, `stopwatch` и
`timer` рендерятся и работают через Bridge-функции.

Несмотря на то, что проект всё ещё в ранней стадии, основные сценарии
UI и Lua-взаимодействия уже проверены на живых модулях.

## Структура

```
lib/
  bridge/
    lua_state.dart       — абстракция над Lua-интерпретатором (реализация на `lua_dardo`, работает)
    bridge_functions.dart — Bridge-функции: time.*, event.*, ui.* (text/column/row/button/input),
                             notify.show (пока эмулируется через EventBus → SnackBar),
                             storage.get/set/delete (работает в памяти процесса, не SQLite)
  event/
    event_bus.dart        — шина событий приложения
  loader/
    module_loader.dart    — единая загрузка встроенных и пользовательских модулей + реестр
  models/
    module_instance.dart  — обёртка над загруженным модулем
  renderer/
    element_renderer.dart — UI-дерево из Lua → Flutter-виджеты (text/column/row/button/input),
                             вызов Lua-колбэков по onTap/onChanged через callLua
  ui/
    home_screen.dart      — список модулей, системный тик раз в секунду, обработка notify.show
  main.dart

assets/modules/
  clock.lua               — эталонный модуль "Часы" (без хранилища, без ввода)
  stopwatch.lua            — Секундомер (состояние в памяти, старт/стоп/сброс)
  timer.lua                — Таймер (ui.input, обратный отсчёт, notify.show по истечении)
  worldclock.lua            — ЧЕРНОВИК: Мировые часы, использует ещё не
                               реализованную time.offset_hours()
  alarm.lua                 — ЧЕРНОВИК: Будильник, упрощённая логика
                               повторяемости без rrule, требует schedule.at()

docs/
  MODULE_API.md              — полный справочник Bridge-функций
  WRITING_MODULES.md         — пошаговый гайд по написанию своего модуля
  BLOCKS_DRAFT.md            — дизайн блоков для будущего визуального сборщика
  FUTURE.md                  — сводка всех отложенных решений и почему они отложены
```

## Что нужно сделать первым делом (день 1 плана)

1. Прототип на отдельной ветке: попробовать `lua_dardo` (`flutter pub add lua_dardo`)
   и, если не зайдёт, FFI-биндинг к `lua.c`. Взять решение — реализовать
   `lua_state.dart` под него. Всё остальное трогать не придётся.
2. После этого — `flutter pub get`, `flutter run`, смотреть, действительно
   ли `clock.lua` рисует часы на экране. Скорее всего конвенция передачи
   `module = M` в глобальную область и то, как именно `getGlobal`/`callField`
   работают с конкретным биндингом — потребуют правки под реальный API
   выбранной библиотеки (сигнатуры в `lua_state.dart` — предположение,
   не проверенный контракт).

## Осознанно не сделано в этом скелете

- `storage.get/set/delete` реально работают, но пишут в `Map` в памяти
  процесса, а не в SQLite — состояние Таймера/Секундомера теряется
  при перезапуске приложения. Заменить на drift, когда дойдёт очередь
  по плану (см. презентацию, неделя 3, день 11) — сигнатуры функций,
  видимые из Lua, при этом не изменятся.
- `notify.show` не показывает системное push-уведомление — эмулируется
  через `EventBus` → `SnackBar` в `HomeScreen`, чтобы можно было проверять
  логику модулей уже сейчас, до подключения `flutter_local_notifications`.
- `_callLua` в `home_screen.dart` перебирает все загруженные модули и
  пробует вызвать колбэк в каждом — это временное решение, пока не
  готова настоящая привязка "колбэк принадлежит вот этому LuaState".
  Не страшно при 3 модулях, станет проблемой при большем количестве —
  поправить одновременно с интеграцией реального Lua-биндинга.
- `schedule.after` / `schedule.at` ещё нет — Таймер сейчас считает через
  `event.on("time.tick", ...)`, то есть работает, только пока приложение
  открыто. Комментарий об этом — прямо в `timer.lua`.
- `worldclock.lua` и `alarm.lua` — черновики, специально НЕ добавлены
  в список загрузки в `home_screen.dart` (`_bootstrap`), потому что
  используют Bridge-функции, которых ещё нет (`time.offset_hours`,
  `schedule.at`) — при попытке загрузить сейчас упадут с ошибкой.
  Подключить их туда можно только после соответствующих недель плана
  (4 и 6).
- Импорт пользовательских `.lua`-файлов через `file_picker` — заглушка
  в `ModuleLoader.loadFromSource` уже есть, UI для выбора файла — нет.
