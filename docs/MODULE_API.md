## time.*

### `time.now()`
Возвращает текущее время как timestamp (мс с эпохи, число).

### `time.format(timestamp, pattern)`
Форматирует timestamp в строку. Поддерживаемые токены в `pattern`:
`HH` (часы, 00-23), `mm` (минуты), `ss` (секунды).

```lua
local t = time.format(time.now(), "HH:mm:ss")
```

**Статус:** реализовано (упрощённый форматтер, без учёта локали).

## event.*

Внутренняя шина событий приложения. Общая для всех модулей —
событие, отправленное одним модулем, могут получить все остальные.

### `event.on(name, callback)`
Подписывает `callback` на событие `name`. Системное событие,
доступное всегда — `"time.tick"` (раз в секунду, пока приложение
открыто).

### `event.off(name, callback)`
Отписывает. **Важно:** отписывайтесь в `onStop`/при остановке
модуля — иначе колбэк продолжит вызываться и после того, как модуль
логически "выключен" пользователем.

### `event.emit(name, data)`
Отправляет своё событие всем подписчикам. `data` — любая
Lua-таблица/значение.

```lua
event.emit("weather.rain", { intensity = "heavy" })
```

**Статус:** реализовано.

## storage.*

Хранилище "ключ-значение", изолированное для каждого модуля —
`storage.get("x")` в модуле A и `storage.get("x")` в модуле B
это два разных значения.

### `storage.get(key)`
Возвращает сохранённое значение или `nil`, если ключа не было.

### `storage.set(key, value)`
Сохраняет значение (число, строка, таблица).

### `storage.delete(key)`
Удаляет ключ.

**Статус:** ⚠️ ЗАГЛУШКА. Сейчас — обычная `Map` в памяти процесса,
данные пропадают при перезапуске приложения. Будет заменено на
SQLite (drift) — план: неделя 3, день 11. Сигнатуры не изменятся.

## ui.*

Строит дерево интерфейса. Вызывается внутри `M.ui()` каждый раз,
когда модуль перерисовывается.

### `ui.text(content)`
Текстовая метка.

### `ui.column({ ... })`
Вертикальный список дочерних элементов.

### `ui.row({ ... })`
Горизонтальный список дочерних элементов.

### `ui.button(label, onTap)`
Кнопка. `onTap` — Lua-функция без аргументов, вызывается по нажатию.

### `ui.input(type, value, onChanged)`
Поле ввода. `type` — `"text"` или `"number"` (сейчас поддержаны;
`"date"`/`"time"` планируются вместе с модулями Будильник/Календарь).
`onChanged` получает новое значение (уже приведённое к числу, если
`type == "number"`).

```lua
ui.input("number", M.input_minutes, M.onInputChange)
```

**Статус:** `text`, `column`, `row`, `button`, `input` реализованы.
`ui.file_picker`, date/time-варианты `input` — не реализованы,
запланированы под модуль Календарь.

## schedule.* — *ещё не реализовано*

Планируется для надёжных отложенных действий (в отличие от
`event.on("time.tick")`, которое работает только пока приложение
открыто):

```lua
schedule.after(30, "minutes", function() ... end)
schedule.at(timestamp, function() ... end)
```

Внутри должно регистрировать системное уведомление/задачу через ОС,
а не JS/Lua-таймер — иначе не переживёт сворачивание приложения.
См. обсуждение в `timer.lua` и в презентации плана (неделя 5).

## Жизненный цикл модуля (не Bridge, но обязательные соглашения)

Каждый `.lua`-файл должен вернуть таблицу с этими (необязательными,
кроме `ui`) полями:

| Поле | Когда вызывается | Обязательно |
|---|---|---|
| `M.init()` | один раз при загрузке модуля | нет |
| `M.ui()` | перед каждой перерисовкой | **да** |
| `M.onStart()` / `M.onStop()` | по соглашению, не системный хук — вызывайте сами из `ui`-колбэков | нет |

В конце файла обязательно:
```lua
module = M
return M
```
