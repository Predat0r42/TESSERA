# Как написать свой модуль

Этот гайд — то, что в итоге увидит пользователь TESSERA, если
захочет написать что-то своё. Полный справочник функций — в
`MODULE_API.md`, тут — практика на примере.

## Шаг 0. Скопируй эталон

Самый быстрый способ начать — взять `assets/modules/clock.lua`
(самый простой встроенный модуль) и менять его под себя, а не
писать с нуля.

## Шаг 1. Структура файла

Любой модуль — это таблица `M` с функциями, и в конце файла:

```lua
module = M
return M
```

Без этих двух строк модуль не загрузится — движок ищет глобальную
переменную `module`.

## Шаг 2. Минимум, который обязателен — `M.ui()`

Это единственная функция, которую движок вызывает сам и без которой
модуль ничего не покажет:

```lua
local M = {}

function M.ui()
    return ui.text("Привет из моего модуля")
end

module = M
return M
```

Это уже рабочий (по логике) модуль — просто строка текста на экране.

## Шаг 3. Добавь состояние

`M.init()` вызывается один раз при загрузке — там заводятся
переменные, которые должны прожить всё время работы модуля:

```lua
function M.init()
    M.counter = 0
end

function M.ui()
    return ui.column({
        ui.text("Счётчик: " .. M.counter),
        ui.button("Плюс 1", M.increment)
    })
end

function M.increment()
    M.counter = M.counter + 1
end
```

Обрати внимание: `M.increment` передаётся в `ui.button` без скобок —
это ссылка на функцию, а не вызов. С скобками (`M.increment()`) она
выполнилась бы сразу при построении интерфейса, а не по нажатию.

## Шаг 4. Реагируй на время

Если модулю нужно что-то делать каждую секунду — подписывайся на
системное событие `"time.tick"`:

```lua
function M.init()
    M.seconds_passed = 0
    event.on("time.tick", M.onTick)
end

function M.onTick()
    M.seconds_passed = M.seconds_passed + 1
end
```

**Не забывай отписываться** (`event.off("time.tick", M.onTick)`),
когда логически модуль "остановлен" — иначе колбэк будет копиться
и срабатывать, даже когда должен молчать. Смотри, как это сделано
в `stopwatch.lua`: подписка происходит только в `onStart`, отписка —
в `onStop`.

## Шаг 5. Сохраняй данные между запусками

`storage.get/set` работает как обычный словарь, привязанный к
твоему модулю:

```lua
function M.init()
    M.counter = storage.get("counter") or 0
end

function M.increment()
    M.counter = M.counter + 1
    storage.set("counter", M.counter)
end
```

⚠️ Сейчас (в этом скелете) `storage.*` — временная заглушка в памяти,
данные не переживают перезапуск приложения. Код выше уже написан
правильно на будущее — когда заглушку заменят на настоящую базу,
этот код менять не придётся.

## Шаг 6. Покажи уведомление

```lua
notify.show("Заголовок", "Текст уведомления")
```

## Шаг 7. Замени встроенный модуль своим

Если твой файл называется так же, как один из встроенных
(`clock`, `stopwatch`, `timer` — то есть внутри `module.id`, когда
это поле появится в реестре), он займёт его место. Никакого
специального флага ставить не нужно — это и есть смысл того, что
все модули написаны одинаково.

## Частые ошибки

- **Забыл `module = M` в конце** — модуль просто не загрузится, без
  внятной ошибки на экране (пока — см. `docs/FUTURE.md`, п. про
  обработку ошибок).
- **Вызвал функцию со скобками там, где нужна ссылка** (`M.foo()`
  вместо `M.foo`) — в `ui.button`/`event.on` это всегда ссылка,
  без скобок.
- **Не отписался от `time.tick`** — модуль продолжает считать/делать
  что-то, даже когда пользователь нажал "стоп".
- **Индексы с 1, не с 0** — если делаешь что-то со списками
  (`{1,2,3}`), первый элемент — `t[1]`, не `t[0]`.
